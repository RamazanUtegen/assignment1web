# Endterm: изменения и подготовка к защите

Команда KZ Travel, SE-2501: Ramazan Utegen, Ziyadinkhan Kudaibergenuly, Ruzimuhammad. Тема и шесть страниц исходного проекта сохранены.

Сайт: https://ramazanutegen.github.io/assignment1web/

## Что изменено после Assignment 6

- На главной и страницах четырёх городов появился прогноз Open-Meteo: текущая температура, ощущаемая температура, ветер, погода на три дня, максимум/минимум и вероятность осадков. На каждой странице города изначально выбран соответствующий город.
- Прогноз запрашивается при приближении раздела к экрану. Можно сменить город или обновить данные. API не требует ключа; геолокация пользователя не запрашивается.
- Состояния загрузки, успеха, ошибки и сохранённого прогноза явно различаются. Тайм-аут равен 10 секундам. Поздний ответ старого запроса не заменяет новый выбранный город.
- Корректный JSON сохраняется локально на 10 минут. При неудачном обновлении можно показать датированную копию до 24 часов; испорченный или слишком старый кеш не используется. При запрете Local Storage сайт продолжает работать.
- Исправлен реальный баг форм: после успешной проверки поля оставались редактируемыми, поэтому можно было стереть имя и получить «Thank you, !». Теперь проверенные поля блокируются до окончания обработки, имя берётся из снимка подтверждённых данных, затем поля восстанавливаются.
- Фокус при ожидании находится на сообщении формы, а Tab/Shift+Tab в диалоге пропускают заблокированные поля. Escape закрывает мобильное меню и возвращает фокус на его кнопку.
- Исправлены координаты в заголовках городов, убраны конфликтующие классы отступов, главное фото загружается с повышенным приоритетом.
- Без JavaScript видны навигация, исходные фотографии и полные ответы FAQ; лишние заглушки и неработающие интерактивные элементы скрыты.
- Проверка деплоя теперь сверяет и URL из `data-src`; прежняя проверка учитывала преимущественно заглушки.

## Как это связано с лекцией Week 9

| Тема | Пример в проекте |
| --- | --- |
| Promise | `fetch()` возвращает Promise; результат сети приходит позже |
| async / await | `loadForecast()` ожидает ответ и затем `response.json()` |
| HTTP и API | GET к Open-Meteo, проверка `response.ok` перед чтением JSON |
| try / catch / finally | Ошибка превращается в сообщение; finally освобождает таймер и кнопку |
| JSON | Проверяются числовые значения и три дня прогноза; `null` не превращается в 0°C |
| Local Storage | Объект кеша преобразуется в строку через stringify и обратно через parse |
| Таймер и event loop | Таймер отменяет долгий запрос; интерфейс остаётся отзывчивым во время ожидания |

Важно: `await` приостанавливает текущую async-функцию, а не весь браузер. Ответ HTTP 404/503 сам по себе не отклоняет Promise fetch, поэтому нужен `response.ok`. `AbortController` останавливает предыдущий запрос; номер запроса дополнительно защищает от результата, пришедшего не в порядке выбора.

## Пройти перед защитой

1. Откройте сайт и код в редакторе. Покажите структуру HTML, общие CSS и отдельные JS-модули.
2. В поиске городов введите `almaty`, переключите категорию, очистите фильтр. Введите `a` и выберите подсказку стрелками/Enter, затем попробуйте на телефоне.
3. Сохраните город и откройте Saved. Объясните Set, Local Storage и событие обновления списка.
4. В FAQ найдите `guide`. Объясните экранирование регулярного выражения и создание mark из текстовых узлов.
5. Пройдите три шага планировщика, используйте Back, затем Copy my route. Объясните валидацию и callback отображения шага.
6. В блоке погоды смените Almaty на Astana. В Network покажите GET и JSON, в Application — ключ `kz-weather-v1-astana`.
7. Перезагрузите страницу: свежий кеш предотвращает лишний запрос. Кнопка Refresh принудительно обновляет прогноз.
8. В DevTools заблокируйте запрос к `api.open-meteo.com`, затем обновите прогноз. С сохранёнными данными отображается датированная копия; новый город без кеша показывает ошибку и возможность повторить запрос. После демонстрации снимите блокировку.
9. Откройте Contact Us, отправьте пустую форму, затем заполните корректно и отметьте обязательный чекбокс. Во время Please wait поля нельзя менять. Проверьте Tab и Escape.
10. Переключите тему, звёзды, звук и галерею. Покажите, где jQuery, а где обычный JavaScript.

Погода — реальный внешний запрос. Формы остаются честной локальной демонстрацией: сообщений и бронирований они не отправляют.

## Небольшие изменения для тренировки

| Изменение преподавателя | Где искать |
| --- | --- |
| Поменять время свежести кеша | `FRESH_MS` в `js/weather.js` |
| Поменять тайм-аут | `TIMEOUT_MS` в `js/weather.js` |
| Показать другой город по умолчанию | `data-default-city` и selected option в нужном HTML |
| Изменить подпись погодного состояния | `conditions()` в `js/weather.js` |
| Изменить цвет карточек в обеих темах | CSS-переменные `--wash`, `--panel`, `--blue` и `css/endterm.css` |
| Изменить задержку демонстрационной формы | setTimeout в обработчике `kz:form-loading` в `script.js` |
| Добавить слово для поиска города | `data-search-text` на карточке в `index.html` |
| Изменить один день маршрута | `stops` нужного города в `js/experience.js` |

Каждый участник должен самостоятельно выполнить несколько таких правок и объяснить результат. Не меняйте только `forecast_days` с 3 на 5: вместе с ним нужно изменить число отображаемых дней в проверке JSON и подписи интерфейса.

## Проверки и комплект сдачи

`python scripts/verify-endterm.py` проверяет структуру и локальные ресурсы. `node scripts/verify-endterm.cjs` запускает браузерные сценарии. Переменная `KZ_WEATHER_LIVE=1` добавляет проверку настоящего API. Основные тесты используют явно заданные ответы, чтобы ошибки/тайм-ауты и гонки воспроизводились. Их скриншоты: `weather-desktop.png`, `weather-night.png`, `weather-mobile.png`; `weather-live.png` снят с настоящими данными. Результаты — `verification.json`; для живого сайта — `live-verification.json`.

Полная регрессия Assignment 6 проверяет Chromium и Microsoft Edge при 1440 × 1000 и 390 × 844. Архивные скриншоты Assignment 6 сохраняются отдельно от новых результатов. Публикация подтверждается успешным GitHub Pages workflow и сравнением HTML/ресурсов с рабочей копией; запись — `deployment.json`.

`python scripts/package-endterm.py` создаёт `output/KZ-Travel-Endterm.zip`. В него входят текущий сайт, фотографии, шрифты, Bootstrap/jQuery, заметки для защиты и скрипты проверки. Старые отчёты, чужие лекции, Git и временные файлы не включаются. Каждый участник отдельно сдаёт очищенный проект. В новых требованиях PDF-отчёт не указан.

Источники для реализации: присланная лекция Week 9; [документация Open-Meteo](https://open-meteo.com/en/docs); [условия некоммерческого API](https://open-meteo.com/en/terms). Атрибуция Open-Meteo и CC BY 4.0 видна в погодном блоке.
